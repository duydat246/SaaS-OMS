Mức độ là đánh giá của người phân tích. "Đã chạy thử" nghĩa là đã tái hiện bằng lệnh thật; "Suy ra từ code" nghĩa là chưa tái hiện trên app đang chạy.

Lỗi nhỏ hơn

  • refresh() không kiểm tra tài khoản còn ACTIVE (AuthService.java:89).

Rủi ro cần đo thêm: backend giới hạn RAM 320 MB với heap 256 MB, nên có thể bị OOM kill khi tải cao.

Mức nợ kỹ thuật nên xếp lại

MụcĐề xuấtLý do
#1 CORS của nginx Giảm mức Vẫn nên sửa, nhưng token nằm trong sessionStorage và không dùng cookie, nên khó khai thác hơn mức P0.
#2 Prod chạy profile dev Giảm mức application-dev.yml bị gitignore nên image build từ CI không có file này; show-sql và log DEBUG không bật trên production. Vẫn nên tạo profile prod.

#8 CI Tăng mức Mỗi lần push lên dev đều deploy thẳng production mà không chạy test, và setup-vps.md coi đây là quy trình hằng ngày. Git local cũng không thấy nhánh main.

Thứ tự xử lý đề xuất

  1. Kiểm tra VPS ngay (chỉ đọc): xem tab Actions, file compose trên VPS, volume uploads và giá trị APP_MEDIA_SECRET.
  2. Sửa để production chạy đúng: lỗi 1, 2, 5, rồi bỏ CORS trong nginx.
  3. Sửa lỗi người dùng gặp trực tiếp: lỗi 3 và 4, kèm entry point trả 401 (nợ #7), vì interceptor hiện phải coi 403 là hết token.
  4. Bảo vệ dữ liệu: lỗi 6, 7, 8. Lỗi 7 và 8 nằm trong vùng order bị cấm chạm nên cần work order.
  5. Siết CI: chạy test trước khi deploy, tag image theo SHA, tách môi trường, rồi thêm rate-limit cho đăng nhập.
  6. Hoàn thiện sản phẩm: nối dashboard với dữ liệu thật, thêm API user và phân quyền STAFF.

Cần bạn quyết định

dev có đang là production thật không?

Nếu đúng, việc sửa CI (nợ #8) nên làm ngay ở bước 2, và AGENTS.md cần ghi lại đúng thực tế. Nếu không, cần tạo main và chuyển deploy sang đó.
